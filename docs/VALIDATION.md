# 验证范围

以下区分当前个人环境的运行证据、可重复的自动检查，以及尚未进行的跨机器部署实测。仓库不包含私人证据文件或聊天内容。

## 运行链路

已在现有 Windows VM → 自有 FRPS → PC B Cursor 的链路验证：锁屏文字 / 图片 / 文件 / 音频文件发送，文字 / 图片 / 文件 / 语音接收；语音转 WAV，媒体下载哈希；实际扩展宿主 online、Webview ready，指定历史消息和 image / file / voice ready 状态可见。

已验证断线按游标补事件、上传中断续传、稳定命令号去重；缺少真实平台回执时保留 uncertain，不盲目重发。TLS 1.2、错误主机名 / 指纹、无证书和未列白名单设备的拒绝曾在个人环境验证。

UI 使用虚构数据在 260 / 320 / 380 / 520 px 浏览器视口验证固定栏、列表导航、整页聊天与输入区。浏览器预览不是实际编辑器截图。B 端缺少音频设备，因此未以人工听感验收播放效果。

## 0.2.1 接收延迟修改

只读检查发现 3 个消息分库，其中 2 个没有消息表；原生查询单次约 170–190 ms。逐会话重复探测空分库、整轮后再休眠、空闲历史回查和整批通讯录刷新都可能累积等待。

修改为：有变化的会话优先；共享分库表目录缓存；每轮后台回查限额；定期联系人一页一页刷新；消息扫描按起点计算周期，默认 0.5 秒；保留失败退避。新好友按会话定向补录。消息推送、TLS、稳定 ID、历史边界、防撤回和旧发送账本不变。

个人环境已经部署这些修改，账号在线、诊断无适配错误；部署后一轮扫描样本约 297 ms。**没有新的好友测试账号，修改后的真实好友到达耗时尚待人工验收**，不能把扫描时间当作手机发出到插件显示的总耗时。附件还受微信下载、解码和媒体重试节奏影响。

## 可重复检查

```powershell
python -m pytest gateway tools -q
powershell -ExecutionPolicy Bypass -File tools/Check-Scripts.ps1
cd extension
npm ci --ignore-scripts
npm run build
npm test
npm run package
```

后端覆盖加密、篡改、消息分页、命令账本、回执归属、媒体持久任务、发送文件名限制、事件订阅，以及新消息优先、空分库共享目录、缺表公平回查、联系人分批和轮询计时。工具覆盖入网包口令 / 篡改认证。前端覆盖安全文本、即时回显、发送回执合并、草稿、导航竞态、独立应用错误隔离、媒体控件复用和协议流控。GitHub Actions 在 Windows / Linux 验证后端，并构建 VSIX。

## 未完成的验证

- 公开版 Update.ps1 已在现有个人 VM 实跑，保留旧桌面入口、守卫、历史与密钥，当前账号重新就绪。新编写的首次安装、跨用户恢复和 Linux systemd 脚本仍需在全新节点验收；未为了仓库发布重装 VM 或替换服务器。
- 好友底层曾验证，但接收优化后的真人好友计时待测；没有可用测试群，不能把统一模型视为群聊实测通过。
- 不是完整多日稳定性、全断电恢复、所有消息类型的覆盖。微信未落库 / 已损坏丢失的记录无法保证补收。
- 上游 Hook / 客户端版本敏感。公开源码不意味着微信或 Hook 可以按 MIT 重新分发。
